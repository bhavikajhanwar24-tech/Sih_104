# F15 — Tenant consent, notice, retention & data-subject operations

## Decision

Tenant-scoped compliance controls: consent register, call-start notice assets,
encrypted voice-passport embeddings, retention purge, and DSR export/erase.
**Audit chain (`audit_blocks`) is never purged** — blocks store IDs/hashes only,
not personal content.

| Piece | Role |
|-------|------|
| `consents` | MONITORING / VOICE_PASSPORT · GRANTED\|WITHDRAWN\|NOT_REQUIRED |
| `consent_tokens` | OTP-less public acceptance links (hash stored, single-use) |
| `voice_passports` | AES-GCM embedding only (`APP_ENCRYPTION_KEY`) + model version |
| `notice_assets` | Call-start announcement file / TTS script (not call PCM) |
| `tenant_settings` | `retention_days` (7–365), notice text/version, `play_call_notice` |
| `RetentionPurgeScheduler` | Per-tenant `TenantContext.runAs` · `RETENTION_PURGE` audit |

## Schema

`V025__f15_compliance.sql` — tables above + RLS + `fn_find_consent_token` /
`fn_list_active_tenant_ids` (SECURITY DEFINER).

## Privacy

1. No call PCM/transcripts in DB, notice assets, passport rows, or audit payloads.
2. Passport stores **encrypted** non-invertible embedding only; never returned on HTTP.
3. Erasure: delete passport + phones + consents; anonymise name → `Erased #<shortId>`;
   null `caller_employee_id` / `callee_employee_id` on sessions; audit `EMPLOYEE_ERASURE`
   with hash evidence (not the deleted data).
4. Retention deletes aged `session_ticks` / `session_reasons` / `session_extractions` /
   `forensic_dossiers` only — **not** `audit_blocks`.

## Manual verification

### Prerequisites

- Stack up (Postgres + backend :8081 + ml-engine :8000 + frontend :5173)
- Demo TENANT_ADMIN session cookies
- `ML_SERVICE_TOKEN` / `APP_ENCRYPTION_KEY` set

### Script

1. Open `/app/compliance?tab=retention` — set `retentionDays` to 30, notice text, save.
   Confirm audit event `TENANT_SETTINGS_UPDATED`.
2. Store TTS notice asset — confirm `NOTICE_ASSET_UPLOADED` and `noticeAssetId` set.
3. Directory: pick an employee → Consent tab (or DSR): grant MONITORING + VOICE_PASSPORT
   via POST consents (or bulk). Confirm register lists `GRANTED`.
4. Issue public link → open `/consent/<token>` logged-out → Accept → status GRANTED,
   token consumed.
5. DSR: Enrol passport (synthetic) — succeeds only with VOICE_PASSPORT GRANTED.
   Withdraw VOICE_PASSPORT → passport deleted.
6. Export employee JSON — embedding absent; phones/consents present.
7. Erase with confirm `ERASE` — name becomes `Erased #…`, phones gone, sessions null
   employee refs, `EMPLOYEE_ERASURE` audit with `erasureHash`.
8. Purge now — `RETENTION_PURGE` audit with counts; `auditBlocksDeleted=0`.
9. DPDP tab — every row says **supports**; disclaimer present.
10. Fairness tab — `EVALUATION_NOT_RUN` (F16).

### Negative checks

- Enrol without VOICE_PASSPORT consent → `403 CONSENT_REQUIRED`
- `retentionDays` 6 or 366 → rejected
- Public token reuse after accept → 400/404
