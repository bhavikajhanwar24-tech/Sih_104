# F6 — Policy compilation pipeline

LLM-assisted rule extraction → human review → versioned, approved rule sets.
The LLM **never decides** risk; it only proposes DSL rules. Scores and levels stay
deterministic (F7 evaluator consumes ACTIVE sets).

## Empty-LLM diagnosis & fix (2026-09-20)

**Symptom:** after catalogue/prompt extensions, compiles reported “N empty LLM replies” for every
pre-filter candidate and stored **zero** rules (earlier compile on the same docs produced ~7 rules).

### Root causes

1. **Misclassification:** gateway failures (`NO_LLM_PROVIDER`, `CIRCUIT_OPEN`, blank content,
   `SCHEMA_VIOLATION`) were folded into `LLM_EMPTY`, so the UI labelled timeouts/outages as
   “empty replies”.
2. **`done_reason` ignored:** Ollama truncation (`done_reason=length`) looked like empty content
   and was not distinguished from a valid `{"rules":[]}`.
3. **Format schema too strict for gemma 4B:** `additionalProperties:false`, `schemaVersion` as
   `const`, and full 29-path fact enums in `format` caused many empty / invalid structured outputs.
4. **Prompt bias:** example B strongly taught empty lists for “definition/scope” and did not warn
   against emptying obligation clauses (`must` / `above INR`).
5. **Progress bug:** `chunksDone` accumulated across re-runs while `chunksTotal` was overwritten
   from result-row counts → UI like **165/75**.

### What changed vs last working prompt (`11f1452` → HEAD)

| Area | At `11f1452` (worked) | After `55d61bf` / HEAD (broke) | Fix now |
|------|----------------------|--------------------------------|---------|
| Example B | Short “general clause → empty” | Stronger empty teaching for 1.1/1.2/6.1 | Empty **only** for pure defs; never empty when obligation cues present |
| Catalogue enums | Older matchType/status values | DirectoryMatch enums | Unchanged (correct); schema subset uses clause-relevant paths only |
| Ollama `format` schema | Flat-ish but `additionalProperties:false` + `const` | Same + larger fact enum after F7 | Flattened; no `additionalProperties:false`; subset fact enum; validate in Java |
| Gateway | No `done_reason` | Same | Emit `doneReason` / tokens / `num_ctx`; `TRUNCATED` / `EMPTY_CONTENT` |
| Java status | Many failures → `LLM_EMPTY` | Same | `LLM_OK_WITH_RULES`, `LLM_OK_EMPTY`, `LLM_TRUNCATED`, `LLM_UNAVAILABLE`, `LLM_EMPTY_SUSPECT` |

### Why clause 5.1 was previously reduced 3 → 2

Earlier `BLOCK_PROHIBITION` did **not** match `must never` / `never share`, so the language
cap fell through to the default/advice class (**2**). The model proposed **3**, and the
validator clamped it down to 2 (`LEVEL_ADJUSTED`).

**Now:** `must never` / `must not` / `never share|ask|…` set cap **3**. Credential
never-share/ask clauses also get **floor 3**, so a model proposal of **1** is raised to **3**
with `LEVEL_ADJUSTED` (up). Values above the cap are still clamped down.

### Level floor and cap by clause language

| Rule type (clause language) | Floor | Cap | Notes |
|-----------------------------|------:|----:|-------|
| Halt / terminate / disconnect / do not proceed | — | **4** | Cap only; no dedicated floor |
| Hard credential prohibition (`never share/ask` … OTP, PIN, password, CVV) | **3** | **3** | Below → raise; above → clamp |
| Must not accept … unverified | **3** | **3** | Same band as hard block |
| Other block / must-never / must-not / lock (no credential/unverified match) | — | **3** | Cap only unless a floor pattern also matches |
| Approval / verification / dual approval / out-of-band required | **2** | **2** | Soft obligation band |
| Default (no stronger match) | — | **2** | Treated as verify/approval class |

Apply order on compile: raise to floor (if any), then clamp to cap. Each adjustment emits
`LEVEL_ADJUSTED` with direction and the computed `floor=` / `cap=` in the message.
Edit path rejects saves that sit below the floor or above the cap (same bounds).

## What was built

### Rule DSL

- Contract: `docs/contracts/v2/PolicyRule.schema.json` (+ `PolicyCompileResult.schema.json`,
  `FactCatalogue.json` with per-fact `enum` where applicable).
- Java: `policy/dsl` — `Condition`, `PolicyRuleDsl`, `ConditionEnglish`, `FactCatalogue`
  (classpath `policy/fact-catalogue.json`; directory-backed enums overridden from
  `DirectoryMatch` at load).
- Closed condition grammar: `all` / `any` / `not` / `fact+op+value`. No eval.
- Catalogue facts are the only allowed `fact` paths; string facts with enums reject free text
  (e.g. `ask.type=PAYMENT_INSTRUCTIONS`, `caller.status=INACTIVE`).
- Plain English never prints `action is *`. Example:
  `IF the request is a wire transfer above INR 10,00,000 (10 lakh) THEN raise the level to at least 2`.

### Compile quality (validator)

- JSON Schema for the LLM is **built from the fact catalogue** (`FactCatalogue.buildCompileResultSchema()`).
- Number verification (`SourceNumberParser`): Indian/Western grouping + words (`lakh`/`crore`).
  Mismatch → **REJECTED** `VALUE_NOT_IN_SOURCE`.
- Grounding: quote in chunk; `clauseRef` required; definition/scope → `UNGBOUNDED_CLAUSE`;
  single non-discriminating facts rejected.
- Level bounds in code (floor then cap):
  - Credential never-share/ask (OTP/PIN/password/CVV) → floor **3**, cap **3**.
  - Must-not-accept unverified → floor **3**, cap **3**.
  - Approval/verification-required → floor **2**, cap **2**.
  - Halt/terminate → cap **4**; other block/must-never → cap **3**.
  - Below floor → raise + `LEVEL_ADJUSTED` (up); above cap → clamp + `LEVEL_ADJUSTED` (down).
  - `minLevel` 0 rejected.
- After all chunks: near-identical `when`+`minLevel` pairs → `POSSIBLE_DUPLICATE`.
- Manual EDIT: quote + enum + empty + non-discriminating + level-cap checks; Accept blocked on
  hallucination. Validator-REJECTED rules editable via **Edit to fix** → EDITED when valid.

### Fact catalogue API

- `GET /api/v2/policy/fact-catalogue` — UI + LLM prompt share one registry (includes enums).

### Compiler pipeline

- `POST /api/v2/policy/compilations` `{documentIds[], mode: FULL|INCREMENTAL}` (TENANT_ADMIN).
  Max documents: `sentinelvoice.policy-compile.max-documents-per-compile` (**default 1**).
- Async: keyword pre-filter → gateway `policy_compile` → deterministic validation → DRAFT set
  (REJECTED rules are **stored** for review, not dropped).
- Diagnostics: `policy_compile_chunk_results` (V010); zero rules → `COMPLETED_NO_RULES`.
- `POST …/resume`, `POST …/rerun-failed`, `POST …/cancel`.
- **No silent mock** for `policy_compile`: Ollama down → `NO_LLM_PROVIDER` unless
  `LLM_FORCE_MOCK=true` (origin `LLM_MOCK`).

### Versioning & approval

- Flyway `V009` + `V010`. Partial unique index `uq_policy_sets_one_active`; trigger
  `trg_policy_set_approver_ne_submitter`.
- Workflow: DRAFT → Accept/Edit/Reject → Submit → PENDING_APPROVAL → Approve/Reject → ACTIVE.
- Submit requires ≥1 ACCEPTED/EDITED rule without hallucination warnings.
- Audit: `POLICY_COMPILE_*`, `POLICY_SET_*` with `contentSha256`.
- Approvals UI: inbox + **Recent decisions**; Versions + Audit Detail.

### Review UI

- Full-screen review: scrollable proposed rules; **Rejected by validator** (collapsed) with
  reason + **Edit to fix**; `possible duplicate` badge; cited-sentence highlight; Delete draft;
  Submit disabled without accepted rules.

## Manual verification script

Prerequisites: backend `:8081`, ml-engine `:8000`, frontend `:5173`, Postgres through V010.
Prefer a live Ollama model. For offline demo only: `LLM_FORCE_MOCK=true` (origin **LLM(mock)**).

### 1 — PDF upload + cited-sentence highlight

1. Sign in as **TENANT_ADMIN**.
2. **Policies → Documents** → upload `Demo_Bank_Quick_Policy_3_Clauses.pdf`. Wait until
   status **Ready** (API `EXTRACTED`). Confirm mime `application/pdf`.
3. Select **one** doc → **Compile (FULL)**. Open **Review workspace**.
4. Click a rule. Left **Source** pane highlights the exact cited quote (`<mark>`).
5. Confirm **Rejected by validator** section lists REJECTED rules with **Edit to fix**.

### 2 — Enum / level-cap / duplicate checks

1. Fact catalogue: `caller.status` has no `INACTIVE`; builder dropdown matches directory.
2. Clause 5.1 / 5.2: model proposing 1 for never-share OTP/PIN is raised to **3** (`LEVEL_ADJUSTED` up).
3. Near-identical adjacent rules show **possible duplicate** badge.

### 3 — Real LLM compile + diagnostics

1. Settings AI / gateway health: Ollama reachable unless force-mock.
2. Compile; progress summary e.g.
   `18 chunks: 10 skipped by pre-filter, 2 rejected by validation, 6 produced rules`.
3. Origin **LLM**. General/definition clauses do not invent rules.

### 4 — Hallucination / value-not-in-source

1. Review → **Advanced JSON** → set `source.quote` absent from chunk → **Save JSON**.
2. Expect **`quote not found in source`**, `HALLUCINATED_QUOTE`, Accept blocked.
3. Amount `1000000000` vs clause `10,00,000` → `VALUE_NOT_IN_SOURCE`.

### 5 — Approval workflow (two users)

1. Admin: **Accept** ≥1 clean rule → **Submit for approval**.
2. Same user → Approvals → **Approve** → blocked (`SAME_USER` + DB trigger).
3. Invite **POLICY_APPROVER** → Approve → **ACTIVE**; prior ACTIVE → **SUPERSEDED**.
4. Demo admin: **Versions** + Approvals **Recent decisions** + Audit (`POLICY_SET_*`).

### 6 — One ACTIVE set (DB)

Paste `scripts/verify_f6.sql` into psql (set `<TENANT_UUID>`). Confirm
`uq_policy_sets_one_active` and ≤1 `ACTIVE` row.

### 7 — Audit chain

Same SQL: recent `POLICY_COMPILE_STARTED`, `POLICY_SET_SUBMITTED`, `POLICY_SET_APPROVED` /
`POLICY_SET_REJECTED` include `contentSha256` and block `hash`.

### 8 — Keywords tab

**Policies → Keywords** → select set → terms by category; add/remove.

### 9 — Housekeeping

Cancel a RUNNING compile; Delete a DRAFT set; confirm UI allows at most **1** doc by default
(`GET /api/v2/policy/compile-limits`).
