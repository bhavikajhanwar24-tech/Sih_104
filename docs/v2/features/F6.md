# F6 — Policy compilation pipeline

LLM-assisted rule extraction → human review → versioned, approved rule sets.
The LLM **never decides** risk; it only proposes DSL rules. Scores and levels stay
deterministic (F7 evaluator consumes ACTIVE sets).

## What was built

### Rule DSL

- Contract: `docs/contracts/v2/PolicyRule.schema.json` (+ `PolicyCompileResult.schema.json`,
  `FactCatalogue.json` with per-fact `enum` where applicable).
- Java: `policy/dsl` — `Condition`, `PolicyRuleDsl`, `ConditionEnglish`, `FactCatalogue`
  (classpath `policy/fact-catalogue.json`).
- Closed condition grammar: `all` / `any` / `not` / `fact+op+value`. No eval.
- Catalogue facts are the only allowed `fact` paths; string facts with enums (e.g. `ask.type`)
  reject free-text / unknown values such as `PAYMENT_INSTRUCTIONS` or `"callback"`.
- Plain English never prints `action is *`. Example:
  `IF the request is a wire transfer above INR 10,00,000 (10 lakh) THEN raise the level to at least 3`.

### Compile quality (validator)

- JSON Schema for the LLM is **built from the fact catalogue** (`FactCatalogue.buildCompileResultSchema()`):
  `fact` is an enum of catalogue paths; leaf values are type-checked in Java after parse.
- Number verification (`SourceNumberParser`): Indian grouping (`1,00,00,000` → 10000000),
  Western grouping, and words (`ten lakh`, `one crore`, `10 lakh`). Every numeric literal in
  `when` must equal a number found in the cited chunk, else **REJECTED** with
  `REJECTED_VALUE_NOT_IN_SOURCE` (counted as hallucinated in progress).
- Grounding: quote must occur in the chunk (whitespace/quote/dash normalised); missing
  `clauseRef` rejected; definition/scope-only clauses rejected (`UNGBOUNDED_CLAUSE`);
  single non-discriminating facts (e.g. only `session.durationSec`) rejected.
- Level caps enforced in code (not left to the LLM): advice/verify/approval → ≤2;
  block/prohibition → ≤3; level 4 only when the clause explicitly requires
  halt/terminate. Over-cap values are clamped with `LEVEL_ADJUSTED`. `minLevel` 0 rejected.
- Manual EDIT: quote checked against cited chunk text; Save surfaces
  **`quote not found in source`**; rule flagged (`HALLUCINATED_QUOTE`); Accept blocked until fixed.
  Numeric literals re-checked including Indian formats.

### Fact catalogue API

- `GET /api/v2/policy/fact-catalogue` — UI + LLM prompt share one registry (includes enums).

### Compiler pipeline

- `POST /api/v2/policy/compilations` `{documentIds[], mode: FULL|INCREMENTAL}` (TENANT_ADMIN).
  Max documents per compile: `sentinelvoice.policy-compile.max-documents-per-compile` (default 5);
  also exposed as `GET /api/v2/policy/compile-limits`.
- Async: keyword pre-filter → gateway task `policy_compile` (90 s/chunk, retry once on
  timeout/schema error) → deterministic validation → DRAFT set.
- Prompt: short system instruction + **catalogue subset** for the clause + 2 worked examples
  (one obligation → rule; one general clause → `{"rules":[]}`).
- Diagnostics: `policy_compile_chunk_results` (V010); zero rules → `COMPLETED_NO_RULES`.
- `POST …/resume`, `POST …/rerun-failed`, `POST …/cancel`.
- **No silent mock** for `policy_compile`: if Ollama is down → `NO_LLM_PROVIDER` unless
  `LLM_FORCE_MOCK=true` (origin then explicitly `LLM_MOCK`).

### Versioning & approval

- Flyway `V009` + `V010`. Partial unique index `uq_policy_sets_one_active`; trigger
  `trg_policy_set_approver_ne_submitter`.
- Workflow: DRAFT → Accept/Edit/Reject → Submit → PENDING_APPROVAL → Approve/Reject → ACTIVE
  (previous ACTIVE → SUPERSEDED in the same `@Transactional` approve).
- Submit requires ≥1 ACCEPTED/EDITED rule without hallucination warnings.
- Audit: `POLICY_COMPILE_STARTED` (with `contentSha256`), `POLICY_SET_SUBMITTED`,
  `POLICY_SET_APPROVED`, `POLICY_SET_REJECTED`.

### Frontend

- Documents: select ≤ N docs → Compile; Rules tab shows progress summary, Cancel, Re-run failed.
- **Keywords** tab: terms per category with add/remove (`policy_keywords`).
- Review: scrollable rule list with **N rules**; origin badge + source quote; cited-sentence
  `<mark>` highlight; empty-state diagnostics; Delete draft; Submit disabled without accepted rules.

## Manual verification script

Prerequisites: backend `:8081`, ml-engine `:8000`, frontend `:5173`, Postgres through V010.
Prefer a live Ollama model. For offline demo only: `LLM_FORCE_MOCK=true` (origin will be
**LLM(mock)**).

### 1 — PDF upload + cited-sentence highlight

1. Sign in as **TENANT_ADMIN**.
2. **Policies → Documents** → upload a policy PDF (or TXT with “must not… / INR …”). Wait until
   status **Ready**.
3. Select doc → **Compile (FULL)**. Open **Review workspace**.
4. Click a rule. Left **Source** pane highlights the exact cited quote (`<mark>`).

### 2 — Real LLM compile + diagnostics

1. Settings AI / gateway health: Ollama reachable (not degraded) unless force-mock.
2. Compile; Rules progress shows summary e.g.
   `12 chunks: 8 skipped by pre-filter, 2 timed out, 2 produced rules`.
3. Proposed rules show origin **LLM** when Ollama served them. General/definition clauses do
   not invent rules (`COMPLETED_NO_RULES` or empty).

### 3 — Hallucination check on edit

1. Review → **Advanced JSON** → set `source.quote` to text absent from the chunk → **Save JSON**.
2. Expect **`quote not found in source`**, `HALLUCINATED_QUOTE` warning, status **PROPOSED**.
3. **Accept** remains blocked until the quote is fixed.
4. Optional: amount `1000000000` vs clause `1,00,00,000` → value-not-in-source.

### 4 — Approval workflow (two users)

1. Admin: **Accept** ≥1 clean rule → **Submit for approval**.
2. Same user → Approvals → **Approve** → blocked (`SAME_USER` + DB trigger).
3. **Users** → invite a second user with role **POLICY_APPROVER**.
4. Sign in as that user → **Approve** → set **ACTIVE**; prior ACTIVE → **SUPERSEDED**.

### 5 — One ACTIVE set (DB)

Paste `scripts/verify_f6.sql` into psql (set `<TENANT_UUID>`). Confirm
`uq_policy_sets_one_active` and ≤1 `ACTIVE` row.

### 6 — Audit chain

Same SQL: recent `POLICY_COMPILE_STARTED`, `POLICY_SET_SUBMITTED`, `POLICY_SET_APPROVED` /
`POLICY_SET_REJECTED` include `contentSha256` and block `hash`.

### 7 — Keywords tab

**Policies → Keywords** → select set → terms by category; add/remove; confirm via SQL counts
on `policy_keywords`.

### 8 — Submit / reject guards

Empty draft: Submit disabled / `NO_RULES`. Reject without comment refused; with comment →
`REJECTED` + audit.
