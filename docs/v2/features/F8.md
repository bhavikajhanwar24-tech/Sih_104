# F8 — Per-tenant fusion configuration and pure fusion engine

Tenant-editable fusion weights, level hysteresis, corroboration guardrails, and
emergency rules live in PostgreSQL (`fusion_configs`). The Decision Plane fusion
path is a pure function of `(config, state, inputs) → (state′, RiskAssessment)`.

## What was built

### Schema (`V015__fusion_configs.sql`)
- `fusion_configs` — versioned DRAFT → PENDING_APPROVAL → ACTIVE / SUPERSEDED / REJECTED
- `platform_fusion_defaults` — seeded from former YAML fusion/intervention values
- `fn_register_tenant` seeds ACTIVE v1 for every new tenant

### Config plane (`com.sentinelvoice.fusion.config`)
| Piece | Role |
|-------|------|
| `FusionConfigDocument` | Immutable parsed JSONB view + `weight(family, narrowband)` |
| `FusionConfigValidator` | Guardrails (weight sum, acoustic ≤0.55, L1&lt;L2&lt;L3&lt;L4, …) |
| `FusionConfigRepository` | JDBC tenant-scoped CRUD / approve / platform default |
| `FusionConfigService` | Draft/submit/approve/reject + SHA-256 + audit |
| `ActiveFusionConfigCache` | Caffeine; invalidated on `FusionConfigActivatedEvent` |
| `FusionConfigController` | `/api/v2/fusion-configs` + what-if replay |

### Engine (`com.sentinelvoice.fusion.engine`)
| Piece | Role |
|-------|------|
| `FusionEngine.tick` | Pure steps a–i (scores, EMA, corroboration, policy floor, emergency, hysteresis) |
| `FusionRuntimeService` | Per-session `FusionTickState`; evaluate + override + what-if |
| `RiskAssessment` / `FusionTickInputs` / `FusionTickState` | Records |

`FusionResult.from(RiskAssessment)` keeps `TelemetryFrameBuilder` / reason paths compiling.

### Wiring
- Session open snapshots `fusionConfigVersion` + `policyVersion` (+ null `responsePlanVersion` until F9); audits `SESSION_CONFIG_SNAPSHOT`
- `FeatureFrameIngestService` loads session snapshot (preferred) or cache; calls new engine
- `SentinelProperties.fusion` / `intervention` / `emergency` **deleted** from Java + `application.yml`

## Manual verification

Prerequisites: Postgres through V015, backend `:8081`, logged-in TENANT_ADMIN + distinct POLICY_APPROVER.

1. **Active seed** — `GET /api/v2/fusion-configs/active` returns version 1 ACTIVE with six-family weights summing to 1.
2. **Draft + guardrail** — POST draft, PUT with acoustic weights &gt; 0.55 → 400 `VALIDATION_FAILED`.
3. **Dual control** — submit as admin; approve as same user → 400 `SAME_USER`; approve as approver → ACTIVE, prior SUPERSEDED; cache version bumps.
4. **Session snapshot** — start session; audit `SESSION_CONFIG_SNAPSHOT` has fusion + policy versions; mid-call approve of new config does not change in-flight scores.
5. **Live frame** — ingest FeatureFrame; TelemetryFrame shows smoothed score + level; policy floor reason cites rule when minLevel raises.
6. **What-if** — with session telemetry, POST what-if with alternate weights; returns per-tick scores/levels. Empty telemetry → 400 clear message.
7. **Compile** — `mvn -DskipTests compile` succeeds (no YAML fusion binding).
8. **UI** — open `/app/settings/risk-tuning`; create draft; break acoustic sum &gt; 0.55; confirm inline guardrail; fix; submit; approve as different user.

`responsePlanVersion` is snapshotted at session open (F9). See `docs/v2/features/F9.md`.

### Frontend (`/app/settings/risk-tuning`)
- Settings → **Risk tuning** card (`settings:read`).
- Weight sliders + narrowband toggle; live sum / acoustic-vs-contextual bar; level ladder; inline guardrails.
- Draft / Compare-with-ACTIVE / Submit (TENANT_ADMIN); Approve / Reject (POLICY_APPROVER).
- What-if replay against a session with stored telemetry family scores.
