# F2 — Tenant registration, JWT cookie auth, RBAC, application shell

## What was built

- Public tenant self-registration (`ACTIVE` immediately for hackathon) with log-only `EmailVerificationService`.
- Cookie JWT access (15m) + rotating hashed refresh tokens; Argon2id passwords (BCrypt-12 fallback); login lockout; optional TOTP MFA.
- Central `Role` enum + `@PreAuthorize`; user invite / role change / disable with last-admin guards.
- `GET /api/v2/me` returns `permissions[]` for menu gating.
- Request-scoped `TenantContext` from JWT filter (F3 wires RLS).
- New React shell: react-router, design system in `src/ui`, register/login, `/app/*` guard, Users page.
- Deleted v1 SecurityConfig/Basic demo auth and four-view AppShell switcher.

## API endpoints

| Method | Path | Auth | Notes |
|--------|------|------|-------|
| POST | `/api/v2/public/tenants/register` | public | 201 `{tenantId, slug}` — no tokens |
| GET | `/api/v2/auth/csrf` | public | CSRF cookie + token for double-submit |
| POST | `/api/v2/auth/login` | public | Sets `sv_access` + `sv_refresh` httpOnly cookies; may return `{mfaRequired:true}` |
| POST | `/api/v2/auth/refresh` | public (refresh cookie) | Rotates refresh |
| POST | `/api/v2/auth/logout` | public | Revokes refresh |
| POST | `/api/v2/auth/mfa/enroll` | session | otpauth URI + secret |
| POST | `/api/v2/auth/mfa/verify` | session | Enables MFA |
| POST | `/api/v2/auth/mfa/disable` | session | Requires code if enabled |
| GET | `/api/v2/me` | session | user, tenant, role, mfaEnabled, permissions[] |
| GET | `/api/v2/users` | TENANT_ADMIN, AUDITOR | List |
| POST | `/api/v2/users` | TENANT_ADMIN | Invite |
| POST | `/api/v2/users/{id}/role` | TENANT_ADMIN | Change role |
| POST | `/api/v2/users/{id}/disable` | TENANT_ADMIN | Disable |
| GET | `/api/v2/audit/verify` | session + tenant match | Was permitAll in F1 |

### Register example

```bash
curl -s -X POST http://127.0.0.1:8081/api/v2/public/tenants/register \
  -H "Content-Type: application/json" \
  -d "{\"organisationName\":\"Acme Bank\",\"industry\":\"BANKING\",\"region\":\"IN\",\"adminEmail\":\"admin@acme.test\",\"adminDisplayName\":\"Ada Admin\",\"password\":\"CorrectHorseBattery\",\"acceptedTerms\":true}"
```

### Login example (cookie jar)

```bash
curl -s -c cookies.txt -b cookies.txt -X POST http://127.0.0.1:8081/api/v2/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"tenantSlug\":\"acme-bank\",\"email\":\"admin@acme.test\",\"password\":\"CorrectHorseBattery\"}"

curl -s -c cookies.txt -b cookies.txt http://127.0.0.1:8081/api/v2/me
```

## Permissions (menu / API)

Derived from `Role` — frontend must use `permissions[]`, never role names for nav.

| Role | Notable permissions |
|------|---------------------|
| TENANT_ADMIN | users:*, settings:*, policies:write/submit, response:write/submit, calls:*, directory:*, audit:read, mfa:manage |
| POLICY_APPROVER | policies:approve, response:approve, audit:read |
| ANALYST | calls:read/act, audit:read |
| AUDITOR | read-only across audit/config/users/policies/response/directory |
