# F1 — PostgreSQL 16 + Flyway foundation

## What was built

- Replaced H2 entirely with PostgreSQL 16 (Docker) + Flyway migrations.
- Split DB roles: `sv_owner` (migrations) vs `sv_app` (runtime, no BYPASSRLS).
- Baseline schema: `tenants`, `tenant_settings`, `users`, `audit_blocks` (+ immutability).
- Bootstrap tenant (`slug=bootstrap`, fixed UUID) via `V002`.
- Rewrote audit ledger for per-tenant sequences, advisory locks, new hash rule.
- `GET /api/v2/audit/verify?tenantId=...`
- Deleted disposable v1 JPA tables/entities; dependent services fail fast until later features.

## API endpoints

| Method | Path | Role | Notes |
|--------|------|------|-------|
| GET | `/api/v2/audit/verify?tenantId={uuid}` | authenticated (own tenant) | Returns `{valid, blocksChecked, firstBrokenSeq}` — authz tightened in F2 |

### Example

```bash
curl -s "http://127.0.0.1:8081/api/v2/audit/verify?tenantId=00000000-0000-4000-8000-0000000000b1"
# {"valid":true,"blocksChecked":0,"firstBrokenSeq":null}
```

## How to run

```bash
cd Sih_104
copy .env.example .env   # Windows; or cp on Unix
docker compose up -d postgres
# Postgres is on host port 15432 (maps to 5432 in the container)
cd backend
# Spring does not auto-load .env — defaults match .env.example, or set DB_* in the shell:
& ..\tools\apache-maven-3.9.9\bin\mvn.cmd -DskipTests spring-boot:run
```

### Open psql in the container

```bash
docker compose exec postgres psql -U sv_bootstrap -d sentinelvoice
# or as app role:
docker compose exec postgres psql -U sv_app -d sentinelvoice
```

Useful checks:

```sql
\dt
SELECT id, slug, status FROM tenants;
SELECT seq, event_type, hash FROM audit_blocks ORDER BY seq;
-- Should fail (immutable):
UPDATE audit_blocks SET event_type = 'X';
```

## Manual verification script

1. `copy .env.example .env` and start Postgres: `docker compose up -d postgres`.
2. Confirm health: `docker compose ps` shows `sentinelvoice-postgres` healthy.
3. Start backend with `DB_*` pointing at `127.0.0.1:5432` (defaults match `.env.example`).
4. Flyway logs should show `V001` and `V002` success; JPA `ddl-auto=validate` should pass.
5. `curl` the verify endpoint with bootstrap tenant id — expect `valid:true`, `blocksChecked:0`.
6. In psql as `sv_app`: `INSERT` into `audit_blocks` is allowed; `UPDATE`/`DELETE` must raise.
7. Confirm no H2: `/h2-console` absent; `application.yml` has no `jdbc:h2`.
