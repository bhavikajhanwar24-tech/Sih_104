# F16 — Alert labelling, metrics, threshold suggestions, fairness

## Decision

Tenant-scoped analyst labels drive precision/FP metrics, deterministic L3
threshold trade-offs (→ DRAFT fusion config), directory-tag fairness with
Wilson CIs, and rule-quality flags on the F14 dashboard. **No voice-inferred
protected attributes.**

| Piece | Role |
|-------|------|
| `session_labels` | CONFIRMED_FRAUD \| FALSE_POSITIVE \| BENIGN_HIGH_RISK \| UNKNOWN |
| `employees.fairness_tags` | Optional language / region / gender / ageBand (tenant-supplied) |
| `tenant_settings.analytics_*` | Fire-rate / FP-contrib limits, fairness min group, label warn |
| `v_analytics_*` / `mv_analytics_rule_fires` | Daily volume + rule fire aggregates |
| `fn_refresh_analytics_mvs` | Periodic MV refresh (scheduler) |

## Schema

`V029__f16_analytics.sql` — labels table + RLS, fairness tags, analytics knobs,
views, materialised rule-fire summary, seed from F12 `review_status`.

## Java

| Piece | Role |
|-------|------|
| `AnalyticsService` | Label upsert (audited), overview, rules, fairness, threshold curve → draft |
| `AnalyticsController` | `/api/v2/analytics/**`, `/api/v2/sessions/{id}/label` |
| `AnalyticsRefreshScheduler` | `fn_refresh_analytics_mvs` every 15m |
| `DashboardService` | Real FP snapshot + `rulesNeedingReview` |
| `SessionsController` | Mark FP / Confirmed also syncs `session_labels` |

Threshold suggestion is **deterministic** over labelled peak scores (ticks or
`peak_score`). Creating a draft still requires dual-control approval (F8).

## Privacy

1. Labels store disposition enums + optional note — never audio/transcripts.
2. Fairness uses **only** optional directory `fairness_tags`; insufficient groups
   show “insufficient data” (no noisy rates).
3. Audit: `SESSION_LABELLED` on every label write.

## Manual verification

### Prerequisites

- Stack up; Flyway applied through V029
- Demo TENANT_ADMIN + ANALYST cookies
- At least one L3+ call in history

### Script

1. Open Call Detail → set label `FALSE_POSITIVE` with a note → Save. Confirm
   badge / GET `/api/v2/sessions/{id}/label` and audit `SESSION_LABELLED`.
2. As supervisor, re-label to `CONFIRMED_FRAUD` → audited.
3. `/app/analytics`: volume chart renders; low-data banner if &lt;30 labels.
4. Threshold slider: summary text updates; **Create draft from suggestion**
   creates DRAFT fusion config (Approvals / Risk tuning).
5. Optional: enter live session id → **Run F8 what-if** (mutated L3 enter).
6. Dashboard FP KPI shows a rate (or “no labels”); rules needing review links
   to Analytics when fire/FP limits exceeded.
7. Directory employee PUT `{fairnessTags:{language:"hi"}}` → Fairness table
   shows group or “insufficient data”.
