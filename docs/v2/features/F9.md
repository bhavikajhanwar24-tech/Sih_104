# F9 — Admin-defined response plans and rewritten actuation

Tenant-editable response plans map risk levels L1–L4 to ordered action steps.
Runtime actuation reads only the **session-snapshotted** ACTIVE plan — never a
hard-coded `switch(level)`.

## What was built

### Schema (`V016__response_plans.sql`)
- `response_plans` — DRAFT → PENDING_APPROVAL → ACTIVE / SUPERSEDED / REJECTED
- `session_actions` — PlanRunner execution log with per-entry idempotency
- `tenant_integrations` — webhook/SMS/supervisor/CBS/ITSM configs; secrets AES-GCM
- `platform_response_defaults` — seeded default ladder; `fn_register_tenant` copies it

### Action catalogue (`GET /api/v2/response/action-catalogue`)
Fixed, code-defined keys including LOG_ONLY, OPERATOR_ADVISORY, WHISPER_WARNING,
REQUIRE_CALLBACK_VERIFICATION, REQUIRE_LIVENESS_CHALLENGE, LOCK_APPROVAL,
SEND_OOB_MFA, NOTIFY_SUPERVISOR, BRIDGE_SUPERVISOR, HOLD_CALL, TERMINATE_CALL,
FREEZE_BENEFICIARY, CREATE_INCIDENT, CUSTOM_WEBHOOK.

### Config plane (`com.sentinelvoice.response`)
| Piece | Role |
|-------|------|
| `ResponsePlanDocument` | Parsed plan JSON + emergency fail-safe plan |
| `ResponsePlanValidator` | Safety floors (L3/L4, non-empty, LOG_ONLY alone) |
| `ResponsePlanService` | Draft/submit/approve/reject + preview + validate |
| `ActiveResponsePlanCache` | Caffeine; invalidated on activate |
| `TenantIntegrationService` | Encrypted secrets (`APP_ENCRYPTION_KEY`) + test ping |

### Actuation rewrite (`com.sentinelvoice.response.execute`)
| Piece | Role |
|-------|------|
| `ActionExecutor` / `ActionExecutorRegistry` | One executor per catalogue key |
| `PlanRunner` | Level-entry runner; schedules steps; audits degrade/override |
| `SessionActionRepository` | Idempotent `(session, level, step, entryToken)` |

**Deleted:** `ActuationService`, `ActuationAction`, `ActuationResult`.
**Kept:** Asterisk ARI/AMI (`AsteriskAriAdapter`, `AsteriskAmiClient`), WebRTC/noop
`CallControlPort` adapters (capabilities are string tokens: HOLD, WHISPER, …).

### Safety floors
- L3 must include LOCK_APPROVAL | REQUIRE_CALLBACK_VERIFICATION | SEND_OOB_MFA
- L4 must include HOLD_CALL | TERMINATE_CALL | BRIDGE_SUPERVISOR **and** NOTIFY_SUPERVISOR
- L1–L4 never empty; LOG_ONLY alone invalid for L3/L4
- L3/L4 changes require approve by a user ≠ submitter (POLICY_APPROVER)
- Missing integrations → “will degrade to advisory” warnings

### Session snapshot
`CallSessionManager` snapshots `responsePlanVersion` + plan document at open
(alongside fusion/policy). Mid-call approvals do not change in-flight actuation.

## Manual verification

Prerequisites: Postgres through V016, `APP_ENCRYPTION_KEY` set (optional; dev fallback exists),
backend up, TENANT_ADMIN + distinct POLICY_APPROVER.

1. **Catalogue** — `GET /api/v2/response/action-catalogue` lists ≥14 actions with schemas.
2. **Active seed** — `GET /api/v2/response/plans/active` returns version 1 ACTIVE with L1–L4 steps.
3. **Safety floor** — PUT draft that empties L4 or removes NOTIFY_SUPERVISOR → 400 `VALIDATION_FAILED`.
4. **Dual control** — submit as admin; approve as same user → 400 `SAME_USER`; approve as approver → ACTIVE.
5. **Session snapshot** — open call; audit `SESSION_CONFIG_SNAPSHOT` includes `responsePlanVersion`.
6. **Actuation** — escalate to L3; `session_actions` shows LOCK_APPROVAL / callback / OOB; no `switch(level)` path remains.
7. **Degrade** — disable telephony adapter capabilities; HOLD failure audits `ACTION_DEGRADED` and falls back.
8. **Integrations** — configure CUSTOM_WEBHOOK, click Test; secrets never returned in clear.
9. **UI** — `/app/response` edit ladder, drag actions, preview L3 with sample facts, submit/approve.
