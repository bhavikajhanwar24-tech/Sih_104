# F3 — Tenant isolation (RLS, API, WebSocket, ML)

## What was built

- PostgreSQL FORCE RLS on all tenant-owned tables; fail closed when `app.tenant_id` unset.
- SECURITY DEFINER platform functions for register / login / refresh lookup.
- `TenantAwareDataSource` + `TenantContext.runAs` / `runAsPlatform`.
- Sessions carry `tenantId`; STOMP topics `/topic/tenant/{tid}/telemetry/{sid}` with cookie JWT + subscribe guard.
- ML `/ws/features` requires `ML_SERVICE_TOKEN`; tenant resolved from Java session registry only.
- ml-engine session open requires service token + opaque `tenantId` + per-tenant concurrency cap.
- Audit list + verify (own tenant only; AUDITOR/TENANT_ADMIN); frontend Audit page.

## SECURITY DEFINER functions

| Function | Purpose |
|----------|---------|
| `fn_find_tenant_by_slug` | Pre-auth tenant lookup |
| `fn_find_user_for_login` | Pre-auth user+hash for login |
| `fn_register_tenant` | Insert tenant + settings + admin user |
| `fn_slug_exists` | Unique slug check |
| `fn_find_refresh_token` | Locate refresh row by hash before `runAs` |
| `app_current_tenant_id` | Helper for RLS policies |
