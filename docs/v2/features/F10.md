# F10 — Multi-tenant telephony (PJSIP REALTIME)

## Decision

Use **PJSIP REALTIME** via PostgreSQL schema `asterisk` (`ps_endpoints`, `ps_auths`,
`ps_aors`, `ps_contacts`). The Asterisk image includes `res_config_pgsql`.

- App tables (`trunks`, `sip_endpoints`, `call_sessions`) stay **FORCE RLS** isolated.
- Role `sv_asterisk` has CONNECT + USAGE/DML on schema `asterisk` only — **no** tenant tables.
- Java provisioning (`SipProvisioningService`) encrypts passwords with `SecretBox`, stores
  ciphertext on `sip_endpoints`, and syncs **plaintext** into `asterisk.ps_*` for digest auth.
- Extension namespaces: `tenants.telephony_ordinal * 1000 + nnn` (ordinal 1 → 1001…).
- Generated `pjsip.conf` includes were rejected: realtime avoids reload races and matches the
  Docker image’s `res_config_pgsql` support.

## Health diagnostics (`GET /api/v2/telephony/asterisk/health`)

Settings → Telephony shows **per-check** status (not a single “unreachable”):

| Check id | What it proves | Typical fix |
|----------|----------------|-------------|
| `postgresRealtime` | Backend `SELECT count(*)` on `asterisk.ps_endpoints` / `ps_auths` / `ps_aors` (via `ASTERISK_SYNC_URL` when set, else primary datasource) | Apply V017/V018; grant `sv_app`; or set `ASTERISK_SYNC_URL` + seed local |
| `asteriskRealtime` | AMI `pjsip show endpoints` at `127.0.0.1:5038` | Publish `127.0.0.1:5038:5038`; `manager.conf` enabled |
| `ari` | `GET {ari.base-url}/asterisk/info` with Basic auth | Host backend must use `http://127.0.0.1:8088/ari` (published port), not Docker DNS name |
| `sipExternalIp` | `SIP_EXTERNAL_IP` non-empty in Spring Environment | Set in `.env`; restart backend (DotEnv loader + `scripts/sv.ps1`) |

Failed checks log at **WARN** without secrets. UI has **Copy diagnostics**.

### Why UI showed “unreachable” / “SIP_EXTERNAL_IP: not set”

1. Health only queried primary JDBC; with Supabase, or without `ASTERISK_SYNC_URL` bean, failures collapsed to a boolean.
2. Host-run Spring Boot did **not** load repo `.env` unless `sv.ps1` exported it — `@Value("${SIP_EXTERNAL_IP:}")` was empty.
3. AMI was not published on the host (`5038`), so Asterisk DB status could not be probed from Java.

**Fixes:** `DotEnvEnvironmentPostProcessor`, `TelephonyHealthService`, compose `127.0.0.1:5038:5038`, loud `SIP_EXTERNAL_IP` ERROR at startup if blank.

## Asterisk realtime config (container)

| File | Role |
|------|------|
| `/etc/asterisk/res_pgsql.conf` | Asterisk **20** name (not `res_config_pgsql.conf`) — `dbhost`/`user`/`password` |
| `/etc/asterisk/extconfig.conf` | `ps_* => pgsql,asterisk,<table>` |
| `/etc/asterisk/sorcery.conf` | `endpoint=realtime,ps_endpoints` (etc.) |
| Module | `res_config_pgsql.so` (Running) |

Lab with Supabase app DB: Asterisk points at **local** Docker Postgres (`ASTERISK_DB_*`); Java mirrors `ps_*` via `ASTERISK_SYNC_URL` held in `AsteriskMirrorJdbc` (not a Spring `DataSource`/`JdbcTemplate` bean — those types would disable Boot auto-config and route every repository to the local mirror, yielding `relation "trunks" does not exist`).

ARI/AMI from **host** Decision Plane: `127.0.0.1:8088` (ARI) and `127.0.0.1:5038` (AMI) — never the Compose service hostname.

## Manual verification (lab acceptance)

Prereqs: stack up (`.\scripts\sv.ps1 up` or backend+frontend+ml), Asterisk healthy, `SIP_EXTERNAL_IP` = your PC LAN IP in `.env`.

1. **Provision**
   - Directory → add employees e.g. Anita (Treasury) and Rahul (CFO) if missing.
   - Open Anita → Telephony → **Create SIP account** → note extension + password (shown once).
   - Zoiper (laptop): SIP account, domain = `SIP_EXTERNAL_IP`, port **5060 UDP**. Status Registered (green in the Directory UI too).
   - Repeat for Rahul on a second client (Linphone / phone).

2. **Call**
   - Rahul dials Anita’s extension → Anita rings → answer → talk.
   - **Live Calls** shows a new live row for your tenant with directory names.
   - Hang up → Live Calls marks Ended; check DB:

```sql
SELECT caller_employee_id, callee_employee_id, peak_level
FROM call_sessions ORDER BY started_at DESC LIMIT 1;
-- both employee ids populated; known_relationships.contact_count incremented for the pair
```

3. **Cross-tenant**
   - Register a second tenant; provision its own extensions (different ordinal block, e.g. 2xxx).
   - Tenant A softphone dials tenant B extension → dialplan **Busy** (resolve requires same-tenant caller).

4. **Wi‑Fi / NAT**
   - Change Wi‑Fi → update **only** `SIP_EXTERNAL_IP` in `.env` → `docker compose up -d --force-recreate asterisk` → restart backend (`.\scripts\sv.ps1 backend`) → two-way audio again. No hard-coded IPs in configs.

```powershell
docker compose exec postgres psql -U sv_bootstrap -d sentinelvoice -c "\dt asterisk.*"
docker compose exec asterisk asterisk -rx "pjsip show endpoints"
docker compose up -d --force-recreate asterisk
.\scripts\sv.ps1 backend
```

Settings → Telephony checks should be green once SIP accounts exist (AMI “No objects found” before provision is still OK for the Asterisk↔DB link).
